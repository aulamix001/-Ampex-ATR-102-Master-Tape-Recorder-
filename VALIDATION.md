# Build and validation — 0.1.1

## Delivered platform

Windows x86-64 VST3 bundle, cross-compiled in Release mode with GCC MinGW-w64 14.2 POSIX and JUCE 7.0.12 (`4f43011b96eb0636104cb3e433894cda98243626`). The plugin is a native PE32+ DLL exporting `GetPluginFactory`, `InitDll` and `ExitDll`. GCC, C++ and pthread runtimes are linked statically; import inspection found only Windows system DLLs. No WebView or Node runtime is used by the VST3. It is unsigned.

## Preset metadata update

Version 0.1.1 embeds the supplied eight names and Portuguese descriptions from `presets/presets.json`, displays the current description below the panel and in the selector tooltip, and changes Low Speed Color to 7.5 IPS. The generated header is checked against the JSON during preset export and by CI. Existing program indices and saved DAW parameters remain compatible; old sessions keep their explicitly saved speed settings.

- Windows processor test executable, executed with Wine 10 on an Xvfb display: PASS. All eight programs processed at 44.1/48/96 kHz with finite bounded output. Linking, inverse autogain, independent L/R restoration, automatic calibration, formula/speed constraints, preset panel preservation and latency-compensated unity bypass passed (149,020 sample and behavioral assertions).
- The Windows VST3 bundle was scanned and instantiated through JUCE's VST3 host implementation and processed an audio block under Wine: PASS (149,023 total assertions including the processor suite).

Captures in `docs/windows-closed.png` and `docs/windows-open.png` were generated by the Windows executable under Wine, not the browser prototype.
- Eight `.atrpreset` files exported using the Windows executable, with all names and descriptions compared to the supplied JSON: PASS (149,037 total assertions including the processor suite).
- Auxiliary native Linux build, processor suite and actual Linux VST3 scan/load/process: PASS for 0.1.0; not rerun for this metadata update.
- Package ZIP integrity and SHA-256 are checked by `scripts/package-windows.py`.

## Unverified / limitations

- Not tested in a Windows installation or a third-party Windows DAW. Wine execution is not equivalent to that validation. No guarantee of perfect behavior in every host is made.
- The GitHub Actions workflow defines a separate Windows Server 2022 / MSVC build and tests; local validation does not establish its remote result.
- Graphics are original procedural approximations guided by the reference images, not pixel-identical manufacturer artwork. No proprietary art or exact circuit/impulse measurements were supplied.
- DSP models tape-like saturation, noise, hum, EQ, crosstalk and modulation approximately. It is not certified hardware-equivalent. SYNC currently uses the same model as REPRO. No separate sync-head response, measured formula impulse responses or component-level circuit simulation is implemented.
- Stereo only; 2x oversampling; all native parameters are automatable. The nominal VU reference is -12 dBFS RMS. Host bypass reports oversampling latency; wow introduces its own short modulation delay.

## Reproduce

See README.md for the Windows MSVC workflow. The cross-build uses `scripts/mingw-x64.cmake` and `MINGW_ROOT`. Run `ATR102Tests --vst3 <bundle>` for a real module load, `--render-ui` for both editor states and `--export-presets` for the factory files. Rebuild Windows tests with the same source before rerunning them.
